# «Google арқылы кіру»: баптау

Сайтқа тек Google арқылы кіруге болады. Кірген адамның «Талдауларым» мен «Зертхана» жұмыстары
Supabase-тегі бұлтқа сақталады да, басқа құрылғыда ашылады. Құпиясөз жоқ, электрондық поштамен тіркелу жоқ.

`tools/data/auth.json` бос тұрғанда бұл мүмкіндік сөнік: батырма көрінбейді, сайт ешқайда сұраныс жібермейді,
бәрі бұрынғыдай тек браузерде сақталады.

Төмендегі қадамдарды бір рет орындайсыз. Шамамен 30–40 минут кетеді.

## 1. Supabase жобасын ашу

1. [supabase.com](https://supabase.com) сайтына кіріп, **New project** басыңыз.
2. Атауы: мысалы, `korkemtaldau`. Дерекқор құпиясөзін ойлап тауып, өзіңізде сақтаңыз (сайтқа керек емес).
3. Аймақ (Region): Қазақстанға ең жақыны, мысалы, Frankfurt (`eu-central-1`).
4. Жоба дайын болғанда, **Project Settings → Data API** бөлімінен **Project URL**-ды көшіріп алыңыз.
   Ол мынадай болады: `https://abcdxyz.supabase.co`. Бұдан әрі `abcdxyz` — жобаңыздың белгісі.

## 2. Google Cloud-та OAuth клиентін жасау

1. [console.cloud.google.com](https://console.cloud.google.com) → жаңа жоба ашыңыз (мысалы, `korkemtaldau`).
2. **APIs & Services → OAuth consent screen** (немесе **Google Auth Platform → Branding**):
   - пайдаланушы түрі: **External**;
   - қосымша атауы: «Көркем шығарманы талдау»;
   - қолдау поштасы: өз поштаңыз;
   - **Authorized domains**: `korkemtaldau.com` және `supabase.co`;
   - рұқсаттар (scopes): тек `openid`, `email`, `profile`. Басқасы керек емес.
3. **Audience** бөлімінде қосымшаны **In production** күйіне ауыстырыңыз. Әйтпесе тек «Test users»
   тізіміндегі адамдар кіре алады.
4. **Credentials → Create credentials → OAuth client ID**:
   - Application type: **Web application**;
   - **Authorized JavaScript origins**: `https://korkemtaldau.com`;
   - **Authorized redirect URIs**: `https://<жоба>.supabase.co/auth/v1/callback`
     (`<жоба>` орнына 1-қадамдағы белгіні жазыңыз, мысалы, `https://abcdxyz.supabase.co/auth/v1/callback`).
5. **Create** басқанда **Client ID** мен **Client secret** шығады. Екеуін де көшіріп алыңыз.
   Client secret-ті репозиторийге, хатқа, чатқа жазбаңыз — ол тек Supabase-ке керек.

## 3. Supabase-те Google-ды қосу, поштаны сөндіру

1. Supabase → **Authentication → Sign In / Providers**.
2. **Google**: Enable деп қосып, Client ID мен Client secret-ті қойыңыз. **Save**.
3. **Email**: сөндіріңіз (Disable). Сонда сайтқа поштамен тіркелу мүлде болмайды.
   Сол бетте **Allow new users to sign up** қосулы тұрсын — әйтпесе Google арқылы да жаңа адам кіре алмайды.
4. **Authentication → URL Configuration**:
   - **Site URL**: `https://korkemtaldau.com`
   - **Redirect URLs**: `https://korkemtaldau.com/**`

## 4. Кестені жасау

1. Supabase → **SQL Editor → New query**.
2. `tools/data/supabase.sql` файлын толық көшіріп қойыңыз да, **Run** басыңыз.
3. **Table Editor**-да `user_data` кестесі пайда болады, жанында «RLS enabled» деген белгі тұрады.

Бұл кестеде әр адамға бір ғана жол бар. Әркім тек өз жолын оқиды, өзгертеді, өшіреді (RLS ережелері).
Бір адамның деректері 1 000 000 таңбадан аспайды. Адам Supabase-тен өшірілсе, оның жолы да өзі өшеді.

## 5. Кілтті сайтқа қосу

1. Supabase → **Project Settings → API Keys**. Ол жерден **anon public** кілтін
   (немесе жаңа жобаларда **Publishable key**, `sb_publishable_…`) көшіріңіз.
2. `tools/data/auth.json` файлын толтырыңыз:

   ```json
   {
     "supabaseUrl": "https://abcdxyz.supabase.co",
     "supabaseAnonKey": "eyJ… немесе sb_publishable_…"
   }
   ```

3. Сайтты қайта құрастырып, тексеріңіз:

   ```
   tools/build.sh /жол/guide.json
   tools/tests/run.sh
   ```

4. `index.html` пен `tools/data/auth.json`-ды commit жасап, push жасаңыз. GitHub Pages бірнеше минутта жаңарады.

### Кілттер туралы маңызды ескерту

- **anon / publishable кілт жария болады — бұл қалыпты.** Ол сайттың бетінде тұрады, кез келген адам көре алады.
  Деректерді кілт емес, 4-қадамдағы RLS ережелері қорғайды.
- **service_role (немесе `sb_secret_…`) кілтін ЕШҚАШАН репозиторийге жазбаңыз.** Ол барлық қорғанысты
  айналып өтеді: оны білген адам барлық пайдаланушының деректерін оқи да, өшіре де алады.
  `account.py` ондай кілтті көрсе, құрастыруды тоқтатады. Кездейсоқ жария болып кетсе, Supabase-те
  бірден жаңасына ауыстырыңыз (**API Keys → Roll**).
- Google Client secret де құпия: ол тек Supabase баптауында тұрады.

## 6. Іске қосылғаннан кейін тексеру

1. Сайтты ашып, жоғарғы оң жақтағы **«Google арқылы кіру»** батырмасын басыңыз.
   Түсіндірме терезесі шығады → **«Google арқылы кіру»** → Google аккаунтын таңдаңыз.
2. Сайтқа қайтып келгенде батырманың орнында аты-жөніңіздің бас әріптері тұрады (Google суреті алынбайды).
3. Бір талдау бастап, бірнеше сөз жазыңыз. 5–10 секундтан кейін бас әріптерді бассаңыз,
   «Бұлтта сақталды ✓» деген жазу шығады. Supabase → Table Editor → `user_data`-да бір жол пайда болады.
4. Басқа құрылғыда (немесе жасырын терезеде) кіріңіз: жұмысыңыз сұраусыз жүктеледі.
5. Екі құрылғыда бір мезгілде әр түрлі өзгеріс жасасаңыз, «Екі түрлі нұсқа бар» деген сұрақ шығады:
   «Осы құрылғыдағыны сақтау» немесе «Бұлттағыны алу».
6. Мәзірдегі «Бұлттағы деректерді өшіру» бұлттағы жолды өшіреді, құрылғыдағы жұмыс қалады.

## Кәмелетке толмағандардың деректері туралы

Бұл заң кеңесі емес, тек ескерту. Сайтты оқушылар қолданады, ал кіргенде олардың аты мен поштасы
Supabase-те сақталады, ал талдаулары шетелдегі серверге (мысалы, Германияға) түседі.

- Қазақстанның «Дербес деректер және оларды қорғау туралы» заңы бар. Онда кәмелетке толмағанның
  деректеріне ата-анасының келісімі және деректерді Қазақстан ішінде сақтау туралы талаптар айтылады.
  Сайт мектепте кеңінен қолданылатын болса, заңгерден немесе мектеп әкімшілігінен кеңес алыңыз.
- Google аккаунтының өзі 13 жасқа (кейбір елдерде 14–16 жасқа) дейін ата-ананың бақылауымен ғана ашылады.
- Кіру міндетті емес: сайт кірмей де толық жұмыс істейді, деректер тек браузерде қалады.
  Оқушыларға мұны айтып, бұлтқа сақтауды ата-анамен келісіп қосуды ұсыныңыз.
- Сайт тек ең қажеттісін сақтайды: аты, поштасы (Supabase Auth) және талдау мәтіндері. Профиль суреті алынбайды.
- Адам өз деректерін сайттың өзінен өшіре алады («Бұлттағы деректерді өшіру»). Аккаунтты толық өшіруді
  сұраса, Supabase → **Authentication → Users**-тен сол адамды өшіріңіз: оның жолы да бірге өшеді.
